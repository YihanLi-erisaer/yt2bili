## 实现与验收记录（2026-09-26）

- 已实现：数据库 v5 迁移及备份、单 AcFun 账号身份绑定、系统凭据库存放 Cookie、扫码 RPC、独立 FIFO、三平台投稿记录、预览编辑、分片/封面/稿件创建适配器、最终创建意图台账及 AC 回执判定。
- 新建任务默认不勾选 AcFun；账号页另设默认关闭的“实验性接入”开关。当前只允许“准备素材并预览”，自动模式不允许选择 AcFun。启用实验功能是用户主动选择网页接口风险，**不等于**完成真实账号验收或平台授权确认。
- 已通过本地模拟的成功、分片失败、创建响应丢失、同源去重、v4 升级与重启待核对测试；前端 TypeScript、生产构建和新建窗口 Playwright 测试已通过。
- 待真实验收：扫码 Cookie 在当前 AcFun 网页会话的适用性、分区 ID 和字段限制、大文件、提交后的稿件审核、条款许可、异常响应与限流。产品页继续明确标为实验性。当前分区使用人工填写 ID，后续应接入经验证的分区列表供选择。

## 1. 结论和产品定位

**项目内部可行，也有可供验证的社区实现路径。** 当前项目已经将同一任务的下载、校验、封面和翻译与分平台投稿分开，并有 Bilibili 每账号独立队列及抖音独立队列。新增 AcFun 可以复用共享素材和投稿记录框架，再增加一条 AcFun 队列。[Y2A-Auto](https://github.com/fqscfqj/Y2A-Auto) 的源码展示了扫码取得 AcFun 网页会话，并调用创作中心网页接口完成分片上传、封面上传和创建稿件的做法。它说明自动投稿有可研究、可实测的技术路径，**不证明接口是官方开放 API、获得第三方使用许可，或在当前日期仍稳定可用**。[登录实现](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_auth.py)、[上传实现](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_uploader.py)

本 PRD 采用“**本机网页会话适配器，实验性显式启用**”作为首期路线。默认关闭；账号页说明风险并要求用户主动启用，未启用时新建窗口的 AcFun 开关禁用。真实账号验收与条款评估仍是正式开放的门槛。若 AcFun 提供正式接入方式，应优先迁移到正式方式。导出素材或打开投稿网页可作为故障后的人工处理入口，但不能显示为自动同步成功。

### 1.1 本次参考仓库带来的事实与边界

- Y2A-Auto README 宣称支持 AcFun / Bilibili 双平台投稿、AcFun 扫码登录；其代码确实包含扫码登录与 AcFun 投稿链路。这是**源码层面的实现证据**，不是本项目的真实账号验收。[README](https://github.com/fqscfqj/Y2A-Auto#readme)、[扫码登录](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_auth.py)、[上传器](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_uploader.py)
- 该实现以网页 Cookie 会话访问创作中心，再使用取得的上传令牌向上传域名分片传输；投稿成功以 `createDouga` 返回的 `dougaId`（AC 号）为依据。媒体分片完成、`createVideo` 返回视频素材 ID，均不是最终稿件成功。[上传器](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_uploader.py)
- 源码中使用的“标题 50、最多 6 个标签、简介 1000”是该实现的本地限制，尚未由 AcFun 正式资料确认；本项目需要实时校验并在预览中要求修正，不静默截断。[上传器限制处理](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_uploader.py)

## 2. 目标、范围与默认假设

### 2.1 目标

- 用户在“新建任务”中主动选择是否同步上传 AcFun；默认关闭。
- 一条 YouTube 任务只下载、校验、准备和翻译一次，可同时面向所选 Bilibili 账号、抖音账号与 AcFun 账号投稿。
- AcFun 有一条独立的 FIFO 上传队列，并发为 1；AcFun 登录、限流或上传失败不阻塞其他平台。
- 各平台分别展示最终投稿内容、进度、回执、失败与待核对状态；允许仅处理失败的平台。

### 2.2 本稿的产品默认假设，待评审

- 保持 Bilibili 为必选目标，每次选择一个 Bilibili 账号；AcFun 和抖音是两个互不依赖的可选目标，可同时勾选。仍最多绑定五个 Bilibili 账号。
- AcFun 首期仅绑定一个账号，匹配当前抖音单账号体验；这是产品范围选择，不是 AcFun 平台上限。
- 沿用当前“准备素材并预览”与“自动投稿”两种模式。预览时一次确认本任务全部已选目标；AcFun 的自动模式以真实账号、当前网页会话方案及平台条款验证通过为条件，独立于抖音的自动能力开关。未通过时勾选 AcFun 禁止自动模式并说明原因，不能静默改变模式。
- 任务创建后目标平台和目标账号不可变；既有任务不补选 AcFun。想对同视频追加平台需要独立的后续需求，避免绕过去重和投稿确认。
- 首期共用源视频和封面，不为 AcFun 自动裁剪、压缩或重新翻译。平台特有的标题、简介、分区、标签、原创/转载及来源字段使用独立快照和校验。
- “已提交”表示取得可信作品提交回执，不表示审核通过或公开可见。

## 3. 用户流程

### 3.1 连接 AcFun

1. 用户在“账号与连接”查看 AcFun 卡片。未扫码、未主动启用实验性接入或适配器暂时不可用时，新建任务的 AcFun 开关不可用。
2. 实验性网页会话方案可用时，用户在应用内发起 AcFun 扫码登录，并在 AcFun 手机端确认。应用以获得的会话访问账号信息，校验稳定账号 ID、会话有效性和当前投稿能力；页面区分“已登录”和“可投稿”。不要求用户在本应用输入 AcFun 密码。可选的 Cookie 文件导入必须单独标为高级入口，默认不用。
3. 退出登录暂停尚未发起的 AcFun 投稿，历史记录继续绑定原账号。更换账号必须先处理旧账号未完成和待核对的 AcFun 记录；不能让新账号接管旧任务。

### 3.2 新建任务

```text
YouTube 视频链接      [                                  ]
Bilibili 目标账号     [ 选择一个账号                     ]
投稿模式              (●) 准备素材并预览  ( ) 自动投稿

[ ] 同步上传抖音       账号或不可用原因
[ ] 同步上传 AcFun     账号或不可用原因

[ ] 我拥有该视频的版权或已获得转载授权
                                      [取消] [加入队列]
```

- AcFun 未绑定、授权过期、能力未开通或状态无法确认时，复选框可见但禁用，显示可执行的下一步和具体原因。
- 实验性网页会话适配器启用时，开关旁简短说明“通过 AcFun 网页会话投稿；平台接口变化时可能暂停”，并提供查看当前连接状态的入口。
- 勾选 AcFun 时展示目标账号和“与其他平台共用素材，独立排队上传”。账号身份或授权状态在窗口打开期间变化，取消原勾选并要求重新确认。
- 如果勾选抖音和 AcFun，两者在预览和自动模式中的资格各自校验；一个目标不可用时，整个新建请求失败并保留表单，不能悄悄省略该目标。
- 未选择 AcFun 的任务不访问 AcFun 服务；AcFun 故障不得影响 Bilibili 或现有抖音任务创建。

### 3.3 准备、预览和投稿

1. 一条父任务完成共用下载、校验、封面和翻译。
2. 详情页展示共用视频及每个平台自己的最终标题、简介、标签、分区、来源声明和账号。AcFun 必填字段由获准接入文档确定；没有确定前不伪造默认分区或限制值。
3. 预览模式确认已选的全部目标，冻结每个平台的投稿快照，再分别入队。自动模式在平台能力允许且素材检查通过后独立入队。
4. Bilibili、抖音、AcFun 的上传可以并行；各自队列内部串行。任一目标失败、等待授权或限流，仅影响该目标。
5. 列表仍显示一条父任务，如“Bilibili 已提交 · 抖音等待上传 · AcFun 待核对”；详情显示每个目标的独立状态和操作。

## 4. 功能需求

### FR-01 授权和开关门禁

- AcFun 可投稿条件至少包含：适配器已在当前版本完成真实验证、目标账号稳定身份已核实、网页会话有效、创作中心返回可用投稿配置，且使用方式经过条款和账号风险评估。自动投稿另有独立能力开关；扫码成功本身不足以证明可投稿。
- 前端展示状态，服务端在 `tasks.create`、预览确认和真正发起上传前重复校验。过期、换号、撤权或服务不可达给出明确状态，不改投其他账号。
- 若只能确认账号登录而无法确认投稿权限，则视为不可选。

### FR-02 独立账号与去重

- 本地最多一个活跃 AcFun 绑定账号，采用平台提供的不可变账号标识；昵称仅用于展示。历史投稿保存当时的账号身份快照。
- 保留现有 `(YouTube 视频 ID, Bilibili 账号)` 去重；AcFun 另外按 `(YouTube 视频 ID, AcFun 应用/接入身份, AcFun 账号身份)` 去重。换一个 Bilibili 账号不能再次给同一 AcFun 账号投稿同一源视频。
- 第二次创建同源任务并勾选重复 AcFun 目标时，整次创建原子拒绝，提示原任务入口；用户明确取消 AcFun 后才能仅创建其他目标。
- 请求超时重发、双击和并发创建必须只产生一个父任务及每平台一条目标记录。失败、取消、已放弃和待核对记录仍占去重身份；只从原记录继续或核对。

### FR-03 共用素材与平台文案

- 共用源文件、校验结果、封面与一次正常翻译结果。AcFun 的标题/简介初始可取共用中文翻译，再由用户单独编辑；不自动复制 Bilibili 专属尾注或抖音文案。
- AcFun 投稿至少能配置并预览标题、简介、分区、标签、原创/转载、原视频链接、来源说明及封面。Y2A-Auto 的创建请求包含 `channelId`、`creationType`、`originalLinkUrl`、`tagNames`、`coverUrl` 和 `videoInfos`，可作为字段清单的起点；字段取值和限制应以实测创作中心与平台资料为准。[Y2A-Auto 投稿字段](https://github.com/fqscfqj/Y2A-Auto/blob/main/modules/acfun_uploader.py)
- 用户选择转载时，原视频链接须进入 AcFun 专属快照；不能仅因任务来源是 YouTube 就未经用户确认地改为“原创”。标题、简介和标签超过当前验证上限时阻止提交并提示编辑，不照搬参考实现的静默截断。
- 只在 AcFun 分支做 AcFun 媒体规格、字段与权限检查。任何 AcFun 限制不应静默改变共用视频或其他平台内容。
- 用户需要自行确认其内容有权在目标平台发布。AcFun 社区条例要求标题、标签与内容匹配、选择正确分区，且禁止侵害著作权或大量无意义转载；相应提示应进入预览与自动模式确认文案。[AcFun 社区管理条例](https://m.acfun.cn/v/?ac=16012740)

### FR-04 独立队列和状态

- 保留最多五条 Bilibili 账号上传队列和一条抖音队列，新增一条 AcFun FIFO 队列。满配时最多七条平台上传通道；共用下载、校验、准备通道不增加重复任务。
- 队列顺序按目标确认且素材可用后取得的持久序号排序。预览未确认不占上传队列。单目标失败退出活动队列；账号级限流/撤权暂停 AcFun 队列，并保留顺序。
- 登录恢复可以唤醒当前会话中等待授权的目标；程序重启后不自动投稿曾中断的任务。创建作品请求可能已发出但无可信回执时标记“待核对”，不得自动重试创建。
- 每个平台独立进度、错误、冷却和重试。部分成功时只重试失败目标；已提交目标不可因父任务重试而重复投稿。

### FR-05 提交回执、保留和清理

- 记录 AcFun 作品 ID/链接及回执来源；仅文件上传完成或取得临时媒体 ID 不算作品已提交。人工核对与接口回执应区分。
- 所有已选目标均可信提交或用户明确放弃，且无待核对、在途上传和保留标志后，才能清理共享素材。
- 取消排队目标仅取消该平台。正在发起作品创建时不能假定取消成功，应等待结果或进入待核对。

### FR-06 兼容与失败体验

- 未勾选 AcFun 的旧 Bilibili/抖音任务在交互、队列和结果上保持既有语义；旧任务迁移后不自动新增 AcFun 目标。
- 平台特有字段校验失败时，AcFun 标记“待处理”，详情展示字段和修复动作；其他目标仍继续。
- AcFun 实验性接入未启用、会话失效或投稿能力被关闭时，新建开关禁用；已有 AcFun 目标保留原账号和结果，不批量丢弃。

## 5. 验收标准

1. 未连接或无有效投稿能力时，AcFun 开关不可勾选；直接调用后端也被拒绝。连接成功后仍需用户主动勾选。
2. Bilibili、抖音、AcFun 可同时被选中并只执行一次共用素材准备；三个目标均有独立、可核对的最终投稿快照。
3. 五个 Bilibili 账号队列与抖音、AcFun 队列互不占位；AcFun 同账号串行 FIFO，Bilibili 上传阻塞不阻止 AcFun 开始。
4. AcFun 登录过期、限流、素材不合规、上传失败时，其他平台仍可完成，任务显示部分结果，素材保留。
5. 同源同 AcFun 账号并发创建只成功一次；改变 Bilibili 账号不能绕过；原请求重放返回原结果。
6. AcFun 创建请求响应丢失或进程崩溃后只查询原操作记录；不能无条件再次创建作品。重启后任何中断目标均需人工继续。
7. AcFun 取得可信作品回执才显示“已提交”；真实平台审核状态另行显示或标为未知。
8. 旧数据库迁移后任务数、BV、抖音投稿、账号身份与历史结果不丢失；没有 AcFun 目标的任务不调用 AcFun 服务。
9. 真实账号验收使用已授权内容，覆盖扫码登录、会话过期、普通及多分片视频上传、封面和分类、`dougaId` 回执、限流、响应丢失、重启与审核状态。模拟测试和参考仓库的可运行代码均不能代替此项。
10. 网页接口变化、会话失效或投稿能力关闭时，AcFun 队列暂停并保留目标及素材；Bilibili/抖音仍正常运行，用户可从原记录人工核对或继续。

## 6. 上线前必须落实

1. 核对 AcFun 当前服务条款及是否允许此类网页会话自动投稿；若获得正式第三方接入资料，以正式路径取代网页接口。Y2A-Auto 的存在本身不构成平台许可。
2. 确认 AcFun 对转载、来源声明、分类、标签和内容审核的具体要求，并用真实账号验证横屏视频、编码、封面和元数据。
3. 按 Y2A-Auto 所示流程在本项目测试账号上验证扫码 Cookie、创作中心上传令牌、分片、视频素材、封面和最终稿件回执；确认是否可在本机完成，无需抖音式服务器中转。不能照搬抖音接口、大小/时长上限或 OAuth 流程。
4. 在当前版本、当前账号完成真实投稿与故障注入前，保持同步开关禁用；开放后标识网页会话适配器的实验性状态。平台改变接口时按能力开关停用并保留未完成记录。
