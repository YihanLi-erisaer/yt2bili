# yt2bili 本地大模型优先翻译 PRD

版本：v1.0 评审稿

日期：2026-09-23

基线：当日工作区代码；桌面开发版 React + Tauri + Python，以及现有 CLI

状态：需求与建议方案，尚未实现。配套文档：[技术实现方案](本地大模型翻译技术实现方案.md)。

## 1. 需求摘要

程序支持在用户电脑上部署并运行开源大语言模型，完成 YouTube 视频标题和简介的中文翻译。默认优先使用本地大模型，DeepL 从唯一翻译服务调整为可选服务和备用服务。用户可以在设置中改为优先使用 DeepL。

本地推理完成后，沿用现有的标题长度限制、简介来源声明、素材预览编辑及投稿流程。

### 1.1 用户已明确的要求

- 能在本机部署并推理开源大语言模型，用于翻译。
- 默认优先使用本地大模型。
- 保留现有 DeepL API 翻译能力，作为备用选项。
- 用户可以选择优先使用本地大模型或 DeepL。

### 1.2 为形成完整方案补充的产品建议

以下为本稿采用的默认设计，不代表用户已逐项确认：

- 首期翻译范围为现有的视频标题和简介，输出简体中文；不增加字幕、语音或视频内容翻译。
- 设置“首选翻译服务”和“首选失败时使用另一服务”两个独立选项；自动切换默认开启。
- 本地优先时，本地失败后尝试 DeepL；DeepL 优先时，DeepL 失败后尝试本地。一次任务最多切换一次。
- DeepL 密钥变为选填；本地服务可用时，无 DeepL 密钥也能完成翻译。
- 首期交付 Windows x64 桌面与 CLI；为现有 macOS 规划保留兼容接口，macOS 完整部署体验需另行真机验收。
- 推荐 Ollama + Qwen3 8B 量化模型作为首轮验证组合，模型最终版本取决于质量和资源实测。
- 首选项是全局设置，新任务记录设置快照；不增加任务创建页的另一组服务选择控件。

## 2. 当前产品与代码现状

- `yt2bili/translate.py::translate_title_and_desc` 直接创建 DeepL 客户端，检查额度并翻译标题、简介；缺少密钥会失败。源语言元数据为中文时直接跳过翻译。
- 简介原文先取前 `max(desc_body_limit * 2, 400)` 个字符，再调用 DeepL；现有能力不是完整长简介翻译。
- `pipeline.py` 在校验后的素材准备阶段调用翻译，并通过全局 `_translate_lock` 串行执行。下载和校验队列可继续运行。
- 标题通过 `clamp_title` 收敛到默认 80 字；`build_description` 将翻译正文和原标题、原作者、原链接组合到默认 2000 字内。
- 当前 `task.title_zh` 非空就跳过翻译；无法据此区分完整翻译、用户编辑或历史遗留结果。
- 桌面端首次配置向导要求检测 DeepL 密钥；设置和任务页提示也围绕 DeepL 设计。
- 桌面密钥存系统凭据库，普通设置存 `settings.json`；CLI 使用 `.env`。桌面已有任务设置快照与中断恢复。
- 仓库另有多账号与单链接任务 PRD，属于并行需求，不能视为已实现。本需求不改变账号、视频任务身份或上传队列数量。

## 3. 目标与范围

### 3.1 目标

1. 只完成本地模型部署，不配置 DeepL，也能准备出可投稿的中文标题和简介。
2. 用户的服务优先级稳定生效，成功时不调用备用服务。
3. 服务不可用时行为可预测，用户能看见实际服务、切换原因和恢复办法。
4. 模型安装后，翻译环节可断网运行；YouTube 下载和 B 站投稿仍需要网络。
5. 修改翻译方案不破坏已有译文、用户编辑、素材和历史投稿记录。

### 3.2 本期必须交付（P0）

- Windows 本地运行时安装引导、模型下载进度、取消与恢复、服务检测、试译。
- 本地模型的启动、加载、推理、空闲资源释放及失败反馈。
- 两种服务优先级、可关闭的自动切换、DeepL 可选配置。
- 桌面和 CLI 共用的翻译路由与错误规则。
- 任务设置快照、实际使用服务记录、译文人工编辑与明确的重新翻译入口。
- 旧设置和旧任务迁移、翻译失败恢复、质量及性能验收。

### 3.3 本期范围外

- 模型微调、训练、RAG、联网搜索、工具调用、语音或字幕翻译。
- 任意远程大模型 API、本地服务向局域网开放、模型市场及无限模型组合。
- 用本次需求改写视频下载、校验、账号选择或投稿机制。
- 默认安装时把数 GB 模型权重直接塞进主程序安装包。
- 宣称任意低配置电脑都能流畅运行或翻译质量必然优于 DeepL。

## 4. 服务选择与切换规则

### 4.1 默认设置

- 首选服务：本地大模型。
- 自动切换：开启；界面紧邻说明“使用 DeepL 时，标题和简介会发送至 DeepL”。
- 本地模型：推荐模型；首次使用需要安装或下载。
- DeepL 密钥：选填，已有密钥保留。
- 仅本地模式：选择本地优先并关闭自动切换；不需要第三种服务枚举。

保存 DeepL 密钥不自动改变首选项，也不重新打开用户已关闭的自动切换。自动切换只影响本次翻译，不修改全局优先级。

### 4.2 必须一致的执行结果

1. **本地优先，本地成功**：使用本地结果，不查询 DeepL 额度、不调用 DeepL。
2. **本地优先，本地失败，允许切换且有 DeepL 密钥**：尝试 DeepL，成功后记录“已切换至 DeepL”及原因。
3. **本地优先，本地失败，没有 DeepL 密钥**：保留失败与素材，提示安装/启动/更换本地模型，或配置 DeepL；不得把原文当成功译文。
4. **DeepL 优先，DeepL 成功**：使用 DeepL，不为本次任务启动或加载本地模型。
5. **DeepL 优先，DeepL 失败，允许切换且本地已部署**：尝试本地，成功后标记实际服务。
6. **首选未配置、未部署或不可连接**：作为首选不可用处理，允许直接尝试已就绪备用服务；不在任务执行中自动下载模型。
7. **自动切换关闭**：只调用首选服务，失败即停止本次翻译。
8. **两个服务都失败**：任务失败，保留素材、原文和已有成功译文，分别给出可操作原因，不进入投稿。
9. **取消或退出**：终止本次等待，不触发备用翻译，不写入半成品。
10. **原文为空或元数据为中文**：按现有跳过规则处理，不调用任何服务，明确记录跳过原因。中文检测规则的局限不包装为完整语言识别能力。

可切换故障包括服务未启动、模型缺失、内存不足、超时、输出格式失败，以及 DeepL 无密钥、鉴权失败、配额耗尽、限流或网络错误。源数据无效、数据库写入失败、用户取消不通过换服务解决。

标题和简介作为一组结果提交；若首选只完成一部分即失败，备用服务重新翻译同一组输入，避免标题和简介分别来自两个服务。可能产生的重复 DeepL 字符消耗应计入诊断记录。

## 5. 用户流程与界面

### 5.1 首次配置

1. 沿用素材目录和基础运行环境步骤。
2. 翻译服务步骤默认选中“本地大模型优先”。
3. 展示模型名称、预计下载量、磁盘及运行条件提示；点击“安装本地翻译组件”后下载运行时和模型。
4. 分开展示组件下载、模型下载、加载、试译状态；完成一次固定短句试译后标记本地可用。
5. 用户也可选择“DeepL 优先”，保存并检测密钥后继续，不强迫下载模型。
6. 至少一个符合当前切换策略的服务可用才能完成翻译配置：仅备用可用时允许继续，但明确提示当前会使用备用。允许关闭向导并稍后配置。

“安装本地翻译组件”是用户可见操作，不在应用启动或任务运行时隐式下载。失败时保留已完成下载，允许重试。网络不可达时提供离线资源包导入说明。

### 5.2 翻译设置页

- 首选服务单选：本地大模型（默认）、DeepL。
- 自动切换开关与实际顺序说明，例如“本地大模型 → DeepL”。
- 本地区域：运行时版本、模型及大小、状态、安装/重试下载/取消下载、检测和试译。
- DeepL 区域：密钥保存与清除、检测连接和额度。密钥保持隐藏。
- 显示试译结果和耗时；检测本地服务不得顺带查询 DeepL。
- P0 设置修改沿用“任务空闲后保存”的限制，并阻止与部署作业冲突；无需同时引入热更新。

状态至少覆盖：未安装、下载中、未启动、模型缺失、加载中、可用、资源不足、版本不兼容、检测失败。每种失败都应提供下一步操作。

### 5.3 任务列表与详情

- 翻译中显示“等待本地翻译”“加载模型”“本地翻译中”“DeepL 翻译中”“正在切换服务”。未知耗时显示阶段，不伪造百分比。
- 详情显示首选服务、实际使用服务、模型版本、是否切换、切换原因、耗时及输入是否截短。
- 人工编辑保持现有行为；编辑后标记“已人工修改”，原翻译来源仍保留。
- 更改全局设置只影响新任务；旧任务重试默认沿用自己的快照。
- 已就绪且未投稿任务可点击“按当前设置重新翻译”，提示将替换哪些已编辑字段。成功后整体替换，失败保留旧译文且回到可预览状态。
- 失败任务可显式选择“使用当前翻译设置重试”；保留原素材目录、账号及其他投稿参数，只更新翻译配置。
- 已投稿、投稿中、投稿待核对任务禁止重新翻译；不得由翻译操作触发投稿。

### 5.4 用户提示示例

- “本地模型未安装。可安装本地翻译组件，或配置 DeepL。”
- “本地推理超时，已切换 DeepL。本次标题和简介将发送至 DeepL。”
- “DeepL 额度不足，正在尝试本地模型。”
- “本地与 DeepL 均未完成翻译，素材已保留。修复服务后可继续。”

## 6. 翻译内容规则

- 忠实翻译，不添加原文没有的事实、结论、营销信息或解释。
- 保留人名、品牌、型号、URL、时间戳、数字及必要段落；专名可根据语境保留原文。
- 仅输出译文，不展示模型思考内容、聊天套话、Markdown 代码围栏。
- 标题仍最多 80 字；简介连同来源声明最多 2000 字。长度收敛和声明生成由程序负责。
- 首期沿用现有简介截取范围，并记录“输入截短”；不得声称已经翻译完整长简介。完整原文保留供查看。
- 来源声明使用原始元数据，由程序添加一次，不交给模型生成。
- 模型结构校验不能证明语义完全正确；继续保留人工预览编辑与现有可选自动投稿模式。

## 7. 部署与资源体验

- 先联网下载运行时与模型；就绪后本地翻译不依赖外网账号、密钥或在线推理。
- 模型与运行时保存在应用专用目录，独立于视频素材目录；上传后清理视频不能删除模型。
- 推荐验证档位：16 GB 及以上内存、SSD，优先验证具有约 8 GB 及以上可用显存的设备；这是测试起点，不是已测最低要求。
- GPU 不可用时允许运行时使用 CPU，显示可能较慢；超过限时按照同一切换策略处理。
- 下载前按清单中的实际文件大小检查空间，并预留临时下载与更新空间；不拿权重文件大小当作运行内存需求。
- 不足以运行默认模型时提示资源问题；轻量模型经独立质量验收后才加入支持名单，不静默替换。
- 卸载主程序默认保留模型与任务数据；删除应用管理的模型需要明确操作。用户已有的外部模型不由程序清理。

## 8. 兼容、隐私与可追溯

- 新安装及缺少首选项的旧设置，统一默认本地优先；旧 DeepL 密钥保留，可在本地未部署时承担备用。升级提示说明默认值变化。
- 已排队旧任务缺少翻译快照时，按历史 DeepL 行为补齐，并关闭该旧快照的自动切换；新建任务执行新默认。
- 历史成功译文保留，来源未知就显示“历史译文”，不虚构模型或服务信息。
- 本地模式只接收文本元数据，不接收视频文件或账号 Cookie。DeepL 只接收需要翻译的标题和简介片段。
- 日志默认只记录服务、阶段、时长、错误码和长度；现有日志输出完整中文标题、简介的行为需同步收敛。
- DeepL 密钥继续存系统凭据库；凭据库不可读不能阻止本地优先的健康任务运行。
- 诊断信息保存在本地；本期不增加远程遥测服务。

## 9. 验收标准

### 9.1 功能验收

- **AC-01**：全新配置默认为本地优先；本地部署完成且未配置 DeepL 时，桌面和 CLI 均可完成翻译。
- **AC-02**：本地成功时，DeepL 客户端调用数为零，包括额度查询。
- **AC-03**：切至 DeepL 优先并成功时，不启动本地模型推理。
- **AC-04**：两种方向的自动切换均按规则执行；一次翻译最多切换一次。
- **AC-05**：关闭自动切换后，首选失败不调用备用；两者均失败不投稿、不丢素材。
- **AC-06**：中文及全空文本跳过外部服务；非空标题不得被空译文覆盖。
- **AC-07**：格式错误、超时、模型缺失、资源不足、DeepL 鉴权/额度/限流故障均有明确提示。
- **AC-08**：标题、正文和来源声明符合长度规则；备用结果整组替换，不出现半组结果。
- **AC-09**：取消不触发备用，不落盘迟到结果；界面在取消后 2 秒内反馈停止/取消中状态。
- **AC-10**：设置在重启后保留，排队任务快照稳定，人工编辑不因普通重试或服务切换被覆盖。
- **AC-11**：下载中断后可恢复；重启不把部分模型标成可用；上传清理不影响模型文件。
- **AC-12**：翻译耗时不阻塞下载和校验队列；后续多账号版本共用本地推理并发限额。
- **AC-13**：模型就绪后，隔离外网并关闭备用，仅用本地固定样本完成翻译；不以整个上传流程验证离线能力。
- **AC-14**：重新翻译失败保留旧内容；重翻成功回到预览，绝不自动提交。
- **AC-15**：系统凭据库不可用时本地翻译成功；需要 DeepL 时单独报告凭据问题。

### 9.2 质量与性能验收

以下为建议发布门槛，当前没有实测结果：

- 准备至少 100 组去标识的标题/简介样本，覆盖英、日、韩、混合语言、数字、专名、链接、超长和提示注入文本。
- 两名评审对本地与 DeepL 盲评并处理分歧；至少 95% 样本可直接使用或仅需轻微编辑；不得出现严重事实反转或新增实质信息。
- 自动校验样本的结构正确率达到 99%；最终保存结果的字段、长度和声明规则必须 100% 通过。
- 固定参考硬件、模型 digest、输入长度后，对“标题不超过 120 字符、简介片段不超过 1000 字符”的热启动样本，目标 P95 ≤ 30 秒；冷启动单列，目标 P95 ≤ 90 秒。均需报告失败率，不能只统计成功快样本。
- 接近最大输入、纯 CPU、GPU 与视频校验并行时另外报告耗时和内存峰值，不套用以上短输入目标。
- 质量不过关不得仅以推理可运行作为上线依据；需调整提示词、模型或支持语言范围并重新验收。

## 10. 交付阶段与评审事项

1. **可行性验证**：模型质量、Windows 部署、GPU/CPU、显存竞争和取消行为实测，冻结可发布模型与运行时组合。
2. **业务核心**：统一接口、服务路由、超时与切换、数据快照及 CLI。
3. **桌面体验**：部署向导、翻译设置、进度、重翻、旧版本升级提示。
4. **发布验收**：故障注入、离线验证、干净机器安装、历史数据迁移和队列回归。

无需等待评审即可据本稿拆分任务；正式开发前重点评审自动切换默认开启、反向切换、首发平台及硬件性能门槛。若用户另行指定模型或交付平台，应同步更新配套技术方案。
