# 本地优先翻译：使用与验证

开发分支：`codex/local-llm-translation`。基于 `6481dd1` 独立实现，不包含同时开发中的多账号改造。

## 使用

桌面端在“设置”或“账号与连接”打开“翻译服务”。默认本地优先，DeepL 密钥选填。

1. Windows x64 选择“应用管理”，点击“安装 / 重试下载”，下载固定版本运行时和模型。当前下载总量约 6.7 GB，组件按需安装，不在程序启动时偷偷下载。
2. 安装完成后点击“本地试译”，验证本机模型能加载并输出译文。
3. 如需备用，填写 DeepL 密钥并保留自动切换开关；使用 DeepL 时标题和简介会发给该服务。
4. 仅使用本地时，关闭自动切换。用户也可以把首选服务改为 DeepL。
5. 外部模式只接受回环 HTTP 地址，默认端口 11434，并要求已安装受支持的 Qwen3 8B 模型摘要。应用不安装、删除或结束用户自有服务。

CLI：

```powershell
python -m yt2bili translation setup
python -m yt2bili translation status
python -m yt2bili translation test --provider local_llm
python -m yt2bili translation test --provider deepl
python -m yt2bili translation export D:\offline\yt2bili-model.zip
python -m yt2bili translation setup --offline D:\offline\yt2bili-model.zip
```

配置示例见根目录 `.env.example`。桌面仍不读取 CLI `.env`。试译只调用选中的服务，不自动切到另一服务，便于确认各自是否可用。DeepL 试译消耗少量额度。

## 任务行为

- 成功时不访问备用服务；首选失败最多切换一次。用户取消、源输入无效、存储失败不切换服务。
- 超时、重试有硬预算。同步网络请求放在独立进程中执行，Windows Job Object 负责退出时回收自有子进程树。
- 首次翻译前保存策略快照。旧任务保留历史 DeepL 策略，新任务默认本地；更新设置不重新翻译已有内容。
- “按当前设置重新翻译”只对未投稿的 ready 任务开放，需要明确确认替换标题与简介；失败保留旧内容，成功仍等待预览。
- 普通重试复用人工修改。失败任务可显式“使用当前翻译设置重试”；CLI 对应 `retry --use-current-translation-settings`。
- 标题和简介与来源记录原子提交到 SQLite。文本产物写入失败时阻止投稿，重试从数据库恢复，不重新消耗翻译额度。
- 中文元数据及空文本延续跳过规则，长简介延续片段截取，不声称翻译了全部原文。

## 部署与版本固定

组件根目录为用户数据目录的 `translation/`，独立于视频 `work/`。CLI 和桌面通过该目录的跨进程锁协调。数据库仍各自遵循原有目录规则。

运行时固定为 Ollama 0.34.3 Windows AMD64，下载 ZIP 校验 SHA-256；模型固定 `qwen3:8b` 完整 manifest digest。来源和完整校验值在 `yt2bili/translation/manifest.json`。安装完成后校验模型层，不接受同名标签静默漂移。

数据库 schema 从 1 升至 2，升级前保存 `.pre-translation.bak`。降级程序需要恢复相应备份，保留新库以免丢失升级后任务。如果合并多账号分支，必须统一 schema 版本和任务关联键，不能直接把两份 version=2 当作同一迁移。

## 相对初稿的实现取舍

- 应用管理模式目前按单次请求启动并回收运行时，保证异常退出时释放自有 GPU 资源；不常驻共享服务。外部模式可以复用用户已运行的 Ollama。后续常驻优化必须先解决跨进程所有权与退出引用计数。
- 上下文采用 Qwen byte-BPE 的保守 UTF-8 字节上界，加模板和输出保留量；不额外分发 tokenizer。该方式会比精确 token 计数更早缩短长简介，并记录 `input_truncated`。默认上下文 8192，最低也限制为 8192。
- 当前支持清单只包含固定 8B 模型，不自动切换轻量模型。资源不足时报告原因并按用户策略使用备用服务。
- 本地模型和运行时的实际下载只由用户显式安装触发。本次代码测试不等于真实 8B 模型质量、最低硬件或性能验收。

## 验证方式

2026-09-23 本分支自动验证结果：完整 Python 套件 118 项，首次 117 项通过、1 项因工作树未放置 biliup 跳过；该项随后用本机现有 biliup 的 `--help` 解析模式单独补测。桌面交互测试 8 项通过，启动器测试 3 项通过，TypeScript 检查与 Vite 生产构建通过。PyInstaller 冻结成功，源码及冻结后台的协议、离线素材处理和本机模拟模型翻译烟雾测试通过。上述测试未调用真实 DeepL 或下载运行真实 8B 模型。

```powershell
python -m unittest discover -s tests -v
cd desktop
npm run build
$env:YT2BILI_TEST_PORT = '15420'
npm run test:e2e
```

新增自动测试覆盖优先级、双向降级、凭据隔离、取消与硬限时、真实回环 HTTP 请求子进程、错误 JSON、digest 不符、数据迁移、事务回滚、编辑保护、重翻、后台作业去重、下载续传、校验失败和 ZIP 路径约束。桌面测试使用显式开发预览，不操作真实账号。

实际模型评测入口：

```powershell
python scripts/benchmark_translation.py samples.jsonl --provider local_llm --output local-report.json
```

输入每行一个包含 `title`、`description`、`source_lang` 的 JSON 对象。报告包含全部请求耗时（含失败）、失败数、模型清单和译文，不给出伪造的语义质量分数。报告含样本文本及译文，应按样本的数据权限保存。

发布前仍需：实际模型安装与离线推理、至少 100 组样本双人盲评、指定硬件冷/热启动与显存压力测试、真实 DeepL 少量额度冒烟，以及安装包签名和干净机器验收。仅通过 mock 与界面测试不能宣称这些项目已完成。
