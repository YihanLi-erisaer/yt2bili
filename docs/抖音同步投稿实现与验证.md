# 抖音同步投稿：实现与验证

日期：2026-09-25。状态：本地代码完成、自动化验证通过；未部署外部服务、未执行真实抖音投稿。保留了工作区原有未提交修改，未创建提交或推送。

## 已落地

- 新建任务默认不勾选同步抖音；未登录禁用，后台再次验证账号及绑定版本，不能通过直接 RPC 绕过。
- 本地只允许一个活跃抖音账号。退出登录不换身份；有未完成抖音目标时不可归档换号。原有五个 Bilibili 账号及各自独立 FIFO 保留。
- 下载、校验共用；封面/翻译从 Bilibili 上传通道拆到最多五个共享准备 worker，翻译服务原有全局互斥保留。准备后分流到最多五路 Bilibili 和一路抖音上传。
- 预览模式一起确认已准备好的目标；自动模式各平台独立自动入队。抖音自动能力默认关闭，由获得批准的服务配置启用。视频不为抖音另做自动裁切或二次翻译。
- 抖音文案默认使用翻译标题，单独编辑保存。Bilibili 简介附加信息不发给抖音。未保存的抖音文案会阻止确认按钮；版本快照防止陈旧预览提交。
- 按平台持久保存状态、回执和文案快照。部分成功独立展示，失败只恢复该目标；明确放弃和可恢复取消分开处理。
- 同一抖音账号同源视频在本地及同一授权服务数据库中唯一；换 Bilibili 账号再次同步会原子拒绝，普通 Bilibili 去重规则不变。
- HTTP 上传与创建作品分离，创建前持久 intent、后持久回执。丢失响应、异常退出或平台内部网络错误转待核对，不盲重发；已提交不表示审核通过。
- 登录/限流只暂停抖音通道，正常退出不再开始新投稿。在途结果收敛后才释放共享任务锁；所有目标提交或明确放弃且无保留标志时才清理素材。
- v3 → v4 自动迁移及 `.pre-v4.bak` 备份；更早版本继续走原有迁移链。旧任务不新增抖音投稿；旧 Bilibili-only 操作参数哈希兼容。
- CLI 增加 `run --sync-douyin` 和 `publication show/retry/submit/cancel/abandon/resolve`，等待整个任务的已选目标收敛。

## 代码入口与设计差异

| 范围 | 实际文件 |
| --- | --- |
| v4 数据、目标状态与聚合 | `yt2bili/db.py`、`yt2bili/publications.py` |
| 共享准备、平台子任务与文件锁生命周期 | `yt2bili/scheduler.py` |
| Bilibili 既有安全投稿边界 | `yt2bili/upload_coordinator.py` |
| RPC、账号门禁、单目标操作 | `yt2bili/desktop_service.py`、`yt2bili/douyin.py` |
| 官方 OAuth、API 分片、加密令牌、回执日志 | `yt2bili/douyin_broker.py` |
| 新建任务、账号和结果界面 | `desktop/src/App.tsx`、`Douyin.tsx`、`Accounts.tsx` |
| 测试 | `tests/test_douyin.py`、`desktop/e2e/douyin.spec.ts` |

为缩小原有 Bilibili 上传逻辑的改动，未引入设计稿全部 `publishers/*` 与独立 `asset_manager.py` 文件：父任务唯一持有工作目录锁，两个子任务拥有独立取消事件；最后一个子任务结束时才检查统一清理条件。Bilibili 保留现有 UID 文件锁、凭据续期及在途 attempt marker。

服务实现采用 Python 标准库 HTTP 服务和 SQLite，仅支持单实例、单所有者部署，需置于受限 HTTPS 反向代理后；不是多租户托管平台。桌面不持有抖音应用密钥/平台令牌，仅在系统凭据库保存服务配对密钥。视频经过服务临时磁盘中转并分片上传，因此须预留服务磁盘、连接数限制、代理请求限额与带宽预算。

包含抖音发布记录的 profile **不支持旧式跨目录合并导入**，明确报错而非丢弃子记录或重建投稿身份；需整体备份恢复。尚不提供跨不同服务数据库的全局去重或服务迁移工具。
