# 多账号上传实现与验证记录

日期：2026-09-23。依据《多账号上传与单链接任务 PRD》v1.1 及配套技术实现方案。

## 实现范围

- 单次提交一个 YouTube URL，必须明确一个目标账号；默认准备素材并预览。取消 TXT、多链接及强制重发入口。
- 账号最多五个不同 UID，凭据按账号及版本保存。重复 UID、误扫、并发抢占第六名额受服务与数据库约束。清除凭据仍占名额；全部任务已提交后才可归档，重新添加相同 UID 恢复原身份。
- 任务使用 UUID 主键，按视频与账号去重；工作目录、元数据、进度和日志按任务隔离。账号归属固定，历史任务提供一次性绑定。
- 下载和校验仍各一条共享队列，上传为每账号一条独立串行队列。账号等待登录、冷却或限流时，其他账号继续运行；该账号后续预览任务可准备素材。
- 上传前验证本地与在线 UID，记录上传尝试。账号跨 profile 使用同 UID 文件锁及结束时间计时；取消在提交边界检查，结果不明保留素材并等待人工核对。
- 协议升级 v2，React/Rust/Python 同步更新。桌面显示 2+N 条通道、账号筛选和目标 UID。退出使用准备及状态握手，等待在途投稿结束。
- CLI 使用同一服务与执行锁；Windows CLI/worker 使用 Job Object 约束子进程生命周期。

## 验证方式

所有自动化使用临时数据库、虚构账号和模拟投稿；媒体回归使用本地生成素材。没有读取现有用户凭据、迁移真实用户库或执行真实投稿。

本机原虚拟环境不能启动，采用可用的 Python 3.12 和项目隔离依赖目录运行锁定依赖；未把这些临时运行环境纳入提交。浏览器测试固定单 worker，避免冷启动与 FFmpeg 回归同时占用资源造成启动超时。

- Python 完整回归 104 项通过：保留原媒体质量断言，增加账号、身份、迁移、幂等、并发、取消和导入测试；取消竞争窗口的最后修复另运行完整多账号专项（19 项通过，包含一项新增竞争用例）。
- 并发证据：五个账号的模拟上传通过同一个 Barrier 停留在共同区间；观测总上传数为五、每 UID 峰值为一。退出取消各账号第二项，等待五项在途任务完成。
- 隔离证据：同视频五个任务得到不同目录；修改、提交并清理其中一个，另外四个素材仍存在。失效账号等待登录时，另一账号投稿与后续预览仍完成。
- 进程证据：两个真实本地 Python 进程验证同 UID 文件锁排他、不同 UID 不互斥；真实 Windows 父进程被终止后，工具子进程被 Job Object 回收。
- 前端：8 个 Playwright 用例，覆盖空账号、第五账号选择、五条同视频任务的编辑与筛选、7 条通道、1024×680、主题和预览流程。
- 启动器：3 个 Node 测试；TypeScript/Vite 生产构建；Rust 离线 check/build。
- 集成：源 worker 的 v2 协议与离线媒体自检；真实 WebView → Rust → Python 通信检查；冻结 worker 构建与相同冒烟入口。

## PRD 验收对应

以下列出自动化覆盖点，不代表每条验收中的所有真实平台故障组合均已实测。

- AC-01～05：单 URL/账号门禁、URL 规范化、CLI 禁止批量、幂等重发及参数冲突、事务失败不留任务。
- AC-06～10：容量和并发名额、同视频五账号独立记录、数据库不可改投、UID 不符拒绝、旧二维码取消保护、账号故障隔离。
- AC-11～16：共享阶段回归、五路共同上传、单账号串行、UID 锁及冷却、失效账号队首不阻塞预览。FIFO 由持久序号驱动；限流暂停需人工恢复。
- AC-17～22：原媒体回归、五轮重新下载校验、预览/编辑/确认/重试、独立清理、未知投稿不可自动继续、修复保留 BV。
- AC-23～24：取消与迟到写入、提交前取消、五路关闭等待、进程回收、启动不自动续投。
- AC-25～26：旧库备份与迁移、未来/不兼容 schema 拒绝、旧操作 ID 不重执行、历史账号待确认、导入新目录与源素材保留。
- AC-27～28：按 task_id 和 revision 合并，run_id 区分进度；动态队列、任务筛选、第五账号和同视频任务 UI 测试。
- AC-29～30：自动化与真实平台验收分开；本 PR 未进行五个真实账号的投稿验收。
- AC-31：失效/缺失凭据继续占位，归档释放容量，重新添加原 UID 恢复身份。

## 升级及边界

1. schema v0/v1 升级到 v2 前备份数据库；迁移事务失败回滚。历史任务不猜测账号。原 Cookie 仅在 UID 可确定时复制为待验证账号，原文件保留。
2. 外部目录导入会将可确认的标准布局素材复制到新的 UUID 目录，避免导入后清理影响源项目；自定义来源路径无法确认时保留源文件并要求重新准备。相同视频/账号冲突保存到 import_conflicts，不覆盖已有记录。
3. 回退版本需另存升级后的库，再恢复旧库备份及相应旧版本；备份后的新增任务不在旧库内，素材保留供恢复。旧版与新版不能混用同一数据目录。
4. 本地翻译仍是另一个需求。本次沿用 DeepL，检测到未支持的翻译扩展 schema 时拒绝迁移，不能自动覆盖其表结构。
5. 本次验证目标是 Windows。其他操作系统的异常退出及发布包尚未完成平台验证。
6. **工程自动化通过后仍须完成真实平台验收**：经明确授权，用五个真实账号和有权发布的素材，分别核对目标 UID 与 BV；同时检查真实扫码、凭据续期与限流响应。发布前保留这道人工验收，不能把模拟结果当作平台通过。
